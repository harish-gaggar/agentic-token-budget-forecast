# Two-Stage Context Engineering for Agentic Workflows

Open-source **TABF** implementation, reproducible benchmark, and
**production case-study data** for the research in `paper.pdf` / `paper.tex`.
The work covers two complementary frameworks:

| Stage         | Framework            | What it does                                                            | Where the numbers come from |
| ------------- | -------------------- | ----------------------------------------------------------------------- | --------------------------- |
| Pre-flight    | **TABF**             | Forecasts per-stage token consumption from the task description alone   | 600-task seeded benchmark   |
| In-loop       | **ContextOptimizer** | Trims the live message list before every LLM call inside the agent loop | 14 real LLM calls in prod   |

The two stages are deployed independently in our system; together they
form a closed feedback loop (the optimiser's per-call savings logs feed
the next TABF retraining cycle).

## Quick start (5 minutes)

Requires **Python 3.10, 3.11, or 3.12** (not 3.13+ yet for `numpy` wheels on
PyPI). No Docker required.

```bash
git clone https://github.com/harish-gaggar/agentic-token-budget-forecast.git
cd agentic-token-budget-forecast

# One-shot check: venv + TABF smoke + all experiments + result figures
chmod +x scripts/verify.sh
./scripts/verify.sh
```

Or step by step:

```bash
make venv
.venv/bin/python -c "from tabf import TABF; print(TABF().forecast('Summarise Q1 revenue').total_tokens)"
make experiments    # ~30s: synthetic TABF benchmark + fig_w20r.pdf
make production     # production case-study figures from checked-in CSVs
```

Read the manuscript: open **`paper.pdf`** in the repo (pre-built; no LaTeX needed).

If `pip install` fails behind a corporate index, use public PyPI:

```bash
PIP_INDEX_URL=https://pypi.org/simple make venv
```

## Reproducing the numbers in the paper

### Synthetic benchmark (Sections 5-6, TABF)

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m experiments.run_all --out results
```

That populates `results/` with:

- `main_results.csv`         Table 3
- `stratified_results.csv`   Table 4
- `ablation_results.csv`     Table 5
- `classifier_accuracy.json` Table 6
- `significance.csv`         McNemar p-values
- `manifest.json`            Everything above in one file
- `fig_w20r.pdf`             Figure 2
- `fig_calibration.pdf`      Figure 3 left
- `fig_error_dist.pdf`       Figure 3 right
- `fig_per_type_w20r.pdf`    Figure 4
- `corpus.json`              The 600-task corpus
- `traces.json`              Simulated per-stage traces

Every number in `manifest.json` matches the corresponding cell in the
paper, byte-for-byte, when run with the locked seeds (`corpus_seed=1729`,
`sim_seed=20260514`, train/test split seed `42`,
`GradientBoostingRegressor` `random_state=0`). The simulator uses
`hashlib.sha256` for per-task seeding, so results are stable regardless
of `PYTHONHASHSEED`.

### Production case study (Sections 7-8, ContextOptimizer)

```bash
.venv/bin/python -m experiments.plot_production --out results
```

That regenerates three figures from CSVs already checked into the repo:

- `fig_production_savings.pdf`   per-call savings (log scale)
- `fig_production_costs.pdf`     annualised cost projection
- `fig_layer_attribution.pdf`    per-layer token attribution + ms cost (microbench)

The underlying CSVs come from three independent real-measurement sources:

| Source                                | What it captures                                  | CSV(s)                                                                                  |
| ------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 14 ctx-opt production log lines       | aggregate input-token reduction (72%)             | `production_token_savings_summary.csv`, `production_token_savings_samples.csv` (4 verbatim) |
| BigQuery agent-eval pipeline          | per-turn population distribution (75 + 128 turns) | `production_bq_population_stats.csv`, `production_bq_tracking.csv`                      |
| 100-run optimiser microbench          | overhead + per-layer attribution                  | `optimizer_microbench.csv` (100 rows), `optimizer_microbench_layers.csv` (500 rows)     |
| Derived from the above                | annualised cost (input tokens × public list price)| `production_cost_projections.csv` (derivation documented inline)                        |

The microbench is regenerated by running
`experiments/optimizer_microbench.py` inside the production container
(see the script's docstring for the exact `docker exec` command). The
script depends on `agent.context_optimizer` and `langchain_core` and
is intentionally separate from the synthetic-benchmark pipeline because
the optimiser package lives in a different repository.

### Generic-agent personas

```bash
.venv/bin/python -m experiments.plot_generic_agents --out results
```

The plotting step reads two CSVs already checked in
(`generic_agents.csv` and `generic_agents_layers.csv`) and writes
`fig_generic_agents.pdf`. Those CSVs come from a 100-run benchmark
(four agent personas x 25 random seeds) of the same `balanced()`
preset used in production, run against synthetic message lists shaped
like four different agent types:

| Persona | Shape | Layer it provokes |
| --- | --- | --- |
| ReAct web search   | many small search/browse tool results          | tool-result compression |
| Code-fix           | large file-read payloads, same file re-read    | dedup + tool-result compression |
| Multi-turn research| 6-10 RAG turns, history grows monotonically    | tool-result compression + token-budget selector |
| Polling            | 5-12 calls to `get_status` on a stalled job    | repeated-tool-call clustering |

Regenerating the CSVs requires the same `docker exec` setup as the
microbench; the runner script is `experiments/generic_agents.py` and
its module docstring spells out the exact commands. The aggregate
across the 100 runs is a 70% input-token reduction, with the per-layer
breakdown reported in Table 7 of the paper.

## Using the frameworks in your own code

### TABF (pre-flight forecast)

```python
from tabf import TABF

t = TABF()  # heuristic mode, zero training data
fc = t.forecast("Refactor the user-auth module to use JWT tokens.")
print(fc.task_type, fc.complexity, fc.total_tokens)
```

To use the GBT tier, fit it on agent execution traces:

```python
from tabf import TABF, GBTBudgetModel
from tabf.extractor import extract_signals
from tabf.classifier import classify

gbt = GBTBudgetModel().fit([
    (extract_signals(t), *classify(t, extract_signals(t)),
     true_input_tokens, true_output_tokens)
    for t, true_input_tokens, true_output_tokens in your_traces
])
tabf = TABF(ml_model=gbt)
```

The synthetic-trace generator in `benchmark/` produces calibrated
bootstrap traces if you do not yet have live telemetry.

### ContextOptimizer (in-loop trim)

ContextOptimizer is shipped in a separate repository alongside the
production LangGraph agent it was extracted from. A minimal usage looks
like:

```python
from agent.context_optimizer import balanced
from agent.context_optimizer.adapters import LangChainAdapter

opt = balanced(model="gpt-4o-mini", max_tokens=6000)
adapter = LangChainAdapter()

# Inside your agent node, right before invoking the LLM:
items = adapter.to_items(state["messages"])
items, stats = opt.run(items)
state["messages"] = adapter.from_items(items)
# stats.before_tokens, stats.after_tokens, stats.cost_saved_usd, ...
```

The same `opt.run(items)` works against `OpenAIAdapter` (OpenAI
Chat-Completions dict format) or `GenericAdapter` (plain
`{"role", "content"}` dicts). Adapter implementations are ~100 lines
each.

## Two-stage workflow (proposed; not yet deployed end-to-end)

The two frameworks are designed to compose, but the pairing has not
been deployed. The intended shape:

```python
from tabf import TABF
from agent.context_optimizer import balanced

dispatcher_forecaster = TABF()        # or TABF(ml_model=fitted_gbt)
opt = balanced()                       # framework-agnostic in-loop trimmer

# Dispatch time (proposed, not deployed): forecast and configure the budget.
fc = dispatcher_forecaster.forecast(task)
opt.max_tokens = fc.total_input_tokens + safety_margin   # choose your margin

# Then invoke the agent normally; the optimiser would enforce the
# budget on every LLM call inside the loop.
agent.run(task)
```

Status today:

| Component                                                              | Status                |
| ---------------------------------------------------------------------- | --------------------- |
| TABF forecaster                                                        | evaluated on the 600-task synthetic benchmark; not in production |
| ContextOptimizer                                                       | deployed in one production LangGraph agent (NL-to-SQL over BigQuery); validated on four synthetic personas; `max_tokens` set by static config |
| Six-table BigQuery agent-eval pipeline                                 | deployed (writes per-turn token + trajectory + tool data) |
| `dispatcher.forecast(...) -> opt.max_tokens` glue                      | not yet deployed (open work item)     |
| Closed loop: log realised, retrain GBT, tighten ceiling                | not yet deployed (open work item)     |

Every measured number reported in the paper comes from the
optimiser alone, on conversations whose budget came from static
configuration.
